# Beyond EMC（超越等价）

<img src="src/main/resources/beyondemc.png" width="128" alt="Beyond EMC 图标">

把 **ProjectE（等价交换）的 EMC** 接进 **Beyond Dimensions（超越维度）的维度网络**。

存入时有 EMC 价值的物品会**自动折算成网络 EMC**，并在网络界面或自动化接口里随时兑换回来。
网络拥有一份**自己的、与玩家个人转换台无关的**已学习物品集合。

**Minecraft** 1.21.1 · **NeoForge** 21.1.249 · 许可证 MIT

## 安装

1. 安装 **NeoForge 21.1.249**（用官方 installer；最低不要低于 `21.1.238`，原因见上一节）。
2. 下载并安装两个前置模组，放进 `mods/` 目录：
   - **Beyond Dimensions** —— 见其 [CurseForge](https://www.curseforge.com/minecraft/mc-mods/beyond-dimensions) 页面
   - **ProjectE** —— 见其 [CurseForge](https://www.curseforge.com/minecraft/mc-mods/projecte) 页面

   > ProjectE **不在 Modrinth 上**，请从 CurseForge 获取。
3. 把 `beyondemc-1.21.1-neoforge-<版本>.jar` 放进同一个 `mods/` 目录。
4. 启动游戏。在 **Mods** 列表里应能看到 "Beyond EMC"。

服务端同理：把这三个 jar 放进服务端的 `mods/`，客户端也需要装（本模组是 **BOTH** 端）。

## 快速上手

### 1. 存入物品，把它变成 EMC

打开**维度网络**界面（拿 `beyonddimensions:net_creater` 之类的方式创建/打开网络），
把一组钻石放进去。

它**不会**占库存格子，而是立刻变成网络 EMC —— 聊天栏不会有提示，
但界面里 EMC 那一行的数字会变大。

> 折算用的是**回收价**，与 ProjectE 转换桌烧物品的价格完全一致。

### 2. 网络自动学会了这个物品

每存入一种新物品，它就会被记进**这个网络自己的**学习集合。

> ⚠️ **注意**：这是**网络级**的知识，**与你的个人转换台知识无关**。
> 在个人转换台里学一个物品**不会**让网络学会它；反过来也一样。
> 网络只会通过"存入"积累知识。

想确认网络学会了什么：

```
/beyondemc knowledge list
```

### 3. 从界面兑换回来

保持网络界面打开 —— 你刚存入的钻石会出现在列表里，
显示的数量是 `网络EMC ÷ 购买价`（也就是"这些 EMC 能换出多少个"）。

| 操作 | 效果 |
|---|---|
| **左键** | 换出**一组**（该物品的原版最大堆叠数，钻石即 64）并**吸附到鼠标**（与原版拾取一致） |
| **右键** | 换出**一半**并吸附到鼠标 |
| **Shift + 左键** | **直接放进背包**（原版快捷移动的语义；按能放下的数量裁剪） |

吸附到鼠标时：

- 鼠标上已有**同类**物品 → 合并到堆叠上限，**只扣实际吸附数量**的 EMC
- 鼠标上拿着**别的**物品 → 拒绝并提示（不会交换、也不会把物品丢在地上）
- 余额不足 → 只吸附买得起的数量，**只扣那部分**

**兑换成功时屏幕上不会弹任何提示** —— 物品到手、EMC 数字变小，就是反馈。

> 直接进背包（Shift+左键）时，背包放不下会自动按**能放下的数量**兑换，只扣对应部分的 EMC。
> 背包完全放不下时会拒绝，**不会扣钱**。

### 4. 让自动化也能兑换（可选）

在**超越维度的网络接口**里，把某个物品设为**过滤器**。
只要网络已学会该物品，即使没有库存，接口也会产出它并扣除网络 EMC。

- 接口**必须显式配置过滤器**才会抽取 —— 空过滤器什么都抽不出来，
  所以不用担心"接口把网络 EMC 抽干"
- 接口里有真实库存时走原生抽取，**不扣 EMC**
- 不想开放的话，把配置 `allowInterfaceWithdraw` 改成 `false`

### 5. JEI 配方一键填充（可选）

装了 **JEI** 之后，在维度网络的**合成菜单**里对任意配方点 JEI 的 **+** 按钮：

即使配方材料在网络里**没有库存**，只要网络已经学会它们、且 EMC 够，
材料会被**自动用 EMC 兑换**并填进合成栏 —— 相当于用 EMC 直接合成。

- JEI 是**可选**依赖：不装 JEI 时本模组一切照常，只是没有这个集成
- 填充按**购买价 × 数量**扣费，与手动兑换同价
- 网络余额不足时，只填能付得起的部分
- 想要的材料得**先存入过**（网络学会了才会被算作可用）

## 功能详解

### 存入即折算

| 物品类型 | 行为 |
|---|---|
| 有 EMC 价值（钻石、铁锭…） | **折算成网络 EMC**，并记入学习集合 |
| 无 EMC 价值（石头、泥土…） | 按 BD 原本逻辑作为物品入库 |
| 带非默认数据组件（附魔、耐久、自定义名、容器内容物…） | **默认不折算**，原样入库 |

最后一条是刻意的：折算会**不可逆地销毁组件信息**——一把锋利 V 的钻石剑会被按"钻石剑 + 加成"
计价，但组件拿不回来。想改可以打开配置 `convertComponentItems`（请自行评估后果）。

### 界面里的三类条目

| 情况 | 显示 | 点击行为 |
|---|---|---|
| 网络里有真实库存 | 真实库存数量 | 走 BD 原生取出逻辑 |
| 无库存但买得起 | `floor(网络EMC ÷ 购买价)` | **扣除 EMC 换出物品** |
| 买不起（可兑换数 = 0） | 不显示 | — |

**0.3.0 起，第二类条目是"物化条目"——它们真实存在于网络存储里**（详见下一节）。

### 物化：让"无库存但可兑换"的物品真实存在（0.3.0 新增）

0.2 里，"已学习但无库存"的物品只是客户端现场算出来的一行显示，**服务端不认识它**：
不进存档、其他玩家看不到、第三方物流管道也取不到。

0.3.0 把它变成**服务端按权威数据物化、写进网络存储的真实条目**：

- 数量 = 逐件 `floor(网络EMC ÷ 购买价)`，**各物品彼此独立、不共享预算**。
  例：`EMC=100`、钻石单价 `50`、泥土单价 `1` ⇒ 钻石 2 个 + 泥土 100 个。
- **取出会连带收缩**：取走 1 颗钻石 ⇒ `EMC=70` ⇒ 显示变为钻石 1 个 + 泥土 70 个。
- 已有真实库存的物品不物化（避免和 BD 原生行重复）。
- 这些条目会跟着网络一起**存档、跨维度、多人同步**，`/beyondemc materialize list` 可以直接读到。

唯一权威仍然是 **EMC 池 + 学习集合**，物化条目只是它们的**派生**：随时可以丢弃重建，
所以物化层出问题不会丢任何数据（`/beyondemc materialize rebuild` 一键重建）。

> **显示的数量之和允许超过 EMC**——这是 0.2 就有的口径，不是 bug。
> 防刷物品靠的是「**交付即扣费**」：不论你从界面点击、从网络接口抽取，
> 还是按标签/按槽位把物化条目抽走，都必然扣掉对应 EMC；**余额不足就什么都抽不出来**。

### 经济性

- 存入用**回收价**（`getSellValue`），兑换用**购买价**（`getValue`）
- ProjectE 恒有 `购买价 ≥ 回收价`（由 `covalenceLoss ∈ [0.1, 1.0]` 保证），
  所以**不存在"低买高卖"的套利路径**
- `covalenceLoss` 默认为 `1.0`，即**买卖同价**，此时"存入→取出"是中性循环

### 多人

维度网络是 BD 的机制：网络成员共享同一份 EMC 与同一份学习集合。
兑换权限与 BD 原生取出物品一致（**是该网络成员即可**）。

## 命令

所有命令需要权限等级 2（OP）。带"需要玩家"的必须在游戏内以玩家身份执行。

| 命令 | 说明 | 需要玩家 |
|---|---|---|
| `/beyondemc ping` | 联通性自检：EMC 表状态、当前网络概况 | 否 |
| `/beyondemc selftest` | 完整自检（存储层 / 折算 / 兑换 / 策略 / Mixin 存活性 / 接口兑换 / **物化**） | 否 |
| `/beyondemc emc query` | 查看当前网络 EMC 余额 | 是 |
| `/beyondemc emc add <数量>` | 给网络加 EMC（调试用） | 是 |
| `/beyondemc emc spend <数量>` | 从网络扣 EMC（调试用） | 是 |
| `/beyondemc knowledge list` | 列出网络已学习的物品 | 是 |
| `/beyondemc knowledge clear` | 清空网络的学习集合（调试用） | 是 |
| `/beyondemc materialize list` | 列出物化条目的**实际内容**与**应然内容**（对不上会标出来） | 是 |
| `/beyondemc materialize rebuild` | 按权威数据（EMC + 学习集合 + 价格）重建全部物化条目 | 是 |
| `/beyondemc materialize clear` | 清空物化条目（调试用；下次 EMC 变化或开界面会自动重建） | 是 |
| `/beyondemc exchange <物品> <数量>` | 用 EMC 换取物品（与界面点击走同一套服务端逻辑） | 是 |

## 配置

配置文件：`config/beyondemc-server.toml`（服务端配置，首次启动时生成）

### `[deposit]`

| 项 | 默认 | 说明 |
|---|---|---|
| `enableEmcDeposit` | `true` | 折算总开关。关闭后所有物品按 BD 原逻辑入库 |
| `convertComponentItems` | `false` | 是否折算带非默认数据组件的物品。**打开会销毁附魔/耐久/容器内容物** |
| `emcDepositBlacklist` | 空 | 命中的物品**不折算**。支持 `minecraft:diamond` 与标签 `#minecraft:swords` |
| `emcDepositWhitelist` | 空 | **非空时只折算命中的物品**，优先级高于黑名单 |

### `[exchange]`

| 项 | 默认 | 说明 |
|---|---|---|
| `showVirtualEntries` | `true` | 是否在界面显示"无库存可兑换"的物品 |
| `exchangeRequiresKnowledge` | `true` | 兑换是否必须命中学习集合。**改成 false 会绕开核心规则，不建议** |
| `maxExchangePerClick` | `Long.MAX_VALUE` | 单次点击的兑换数量上限 |
| `allowInterfaceWithdraw` | `true` | 是否允许网络接口用 EMC 兑换物品（自动化向） |
| `exchangeFeedback` | `NONE` | 成功提示方式：`NONE` / `CHAT` / `ACTION_BAR`（失败提示始终走聊天栏） |

### `[materialize]`（0.3.0 新增）

| 项 | 默认 | 说明 |
|---|---|---|
| `materializeItems` | `true` | 物化总开关。**关闭时会【清空】已有物化条目**，行为回到 0.2（由客户端虚拟条目兜底） |
| `materializeMode` | `STORAGE` | 写入模式。`STORAGE` = 写进网络存储（唯一正常模式）；`LEDGER` **当前尚未实现**（等同 `OFF`，会记警告）；`OFF` = 不物化且清空条目 |
| `maxMaterializedItems` | `512` | 物化条目数上限，超出时按"价格升序 + 物品注册名"确定性取前 N |

> 关掉 `materializeItems` **不等于**回到 0.2：物化条目是**真实存储条目**，BD 原生列表照样会渲染它们，
> 所以必须真清空（本模组会自动做）。想彻底回退请见 `docs/plan/ROADMAP-0.3.0.md` §9。

## ⚠️ 卸载前必读

**移除本模组会让所有维度网络里的 EMC 归零。**

原因：EMC 是以"自定义资源类型"的形式存在 BD 的网络存储里的。BD 在反序列化时
对未注册的类型会静默丢弃条目 —— **存档不会损坏，但那部分 EMC 会无声消失**。

网络的学习集合存在网络存档的一个自定义 NBT 键里，卸载后只是被忽略（无害）；
但重新装回来时集合还在，EMC 却已经没了。

**建议**：卸载前先把各网络的 EMC 换成物品取出，例如：

```
/beyondemc exchange minecraft:diamond 64
```

## 已知限制

1. **兑换成功不提示**是刻意的；想开提示改配置 `exchangeFeedback`。
2. **可兑换数为 0 的物品不显示**（而非显示为 0）——因为 BD 的列表会丢弃数量为 0 的条目。
3. **学习集合不区分组件**：学习时经过 ProjectE 的 `getPersistentInfo` 归一化，与转换桌判定一致。
4. **附魔/耐久/改名物品默认不折算**，因此也不会被学习、不能兑换。
   这是为了保护组件信息；打开 `convertComponentItems` 会放弃这层保护。
5. 本模组**不与玩家个人转换台的 EMC 互通**（设计如此）。
6. 命令反馈文本目前是**中文硬编码**，未走翻译键。

## 排查问题

遇到问题先跑：

```
/beyondemc selftest
```

它会逐项检查存储层、折算钩子、读档守卫、兑换服务、策略配置、Mixin 目标存活性、
网络接口兑换，并在日志里给出结论与原因。

日志里带 `[BeyondEMC]` 前缀的行都是有意的诊断输出（含"注入跳过"的具体原因、
"接口兑换"的扣费明细）。启动时也会自动跑一遍自检并写进日志。

### 常见现象

| 现象 | 可能原因 |
|---|---|
| 存入物品后没变成 EMC | 该物品没有 EMC 价值；或带组件且 `convertComponentItems=false`；或 EMC 表尚未就绪（需有玩家登录或 `/reload`） |
| 界面里看不到已学习的物品 | EMC 余额不足（可兑换数为 0 时不显示）；或搜索框过滤掉了 |
| 点击兑换没反应 | 看聊天栏的失败提示；或跑 `/beyondemc selftest` |
| 网络接口抽不出东西 | 接口没有配置过滤器；或该物品未被网络学会；或余额不足 |
| 日志出现"注入跳过：客户端还没有学习集合数据" | 正常现象，同步包稍后会到达 |

## 从源码构建

```bash
git clone https://github.com/<你>/beyondemc.git
cd beyondemc

# 前置模组的 jar 不在仓库里（不重新分发第三方二进制）。
# 构建时会自动从 CurseMaven 拉取，坐标见 docs/VERSIONS.md。
# 若要离线构建，把两个 jar 放进 libs/ 即可（见 libs/README.md）。

./gradlew build
```

Windows 上如果没有配置 `JAVA_HOME`，可用随仓库提供的包装脚本：

```powershell
tools\gradlew-here.cmd build      # 显式指定 JDK 21 并隔离 GRADLE_USER_HOME
tools\play.cmd                    # 双击即可启动客户端（开发用）
```

> `tools/` 下的脚本是 Windows 专用的便利包装，里面的 JDK 路径是机器相关的，
> 换机器时需要改；标准的 `gradlew` 不依赖它们。

产物：`build/libs/beyondemc-1.21.1-neoforge-<版本>.jar`

工程文档（架构、设计决策、调研证据、各阶段实测报告）都在 `docs/` 下。
