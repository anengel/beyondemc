### 1.1 Mixin 目标存活性：BD 升级后第一件要做的事

我们绝大多数 Mixin 用 `require = 0` 优雅降级 —— **失配时不会报错，功能会无声消失**。
阶段 7 为此加了反射核查，启动时直接告诉你：

```
OK   Mixin 目标存活性：核对了 6 个目标，全部存在（4 个客户端专项目标在专用服务器上跳过）
```

升级 Beyond Dimensions 之后，**先看这一行**。若有失配，它会逐条列出：
哪个类的哪个成员不存在了、以及对应的 Mixin 会失效。

### 2.2b 安全性回归（每次涉及兑换的改动都要重跑）

这些是**价值完整性**断言，比功能断言重要。

| 项 | 期望 |
|---|---|
| **附魔物品**（锋利 V 钻石剑）存入 → 不折算、不学习 | 作为真实库存保留 |

| 接口配置已学会的**普通**物品且无库存 | 正常产出，扣费 = `数量 × 购买价`（与日志数字一致） |
| 接口配置已学会物品但**余额不足** | 不产出，EMC 不变 |
| 兑换经济性 | 任意"存入 A → 取出 A"循环**不产生净收益**（`购买价 ≥ 回收价`） |

#### 回退演练怎么跑（可复用，实测过）

见 `docs/testing/phase8-materialize-report.md` §7.2。要点三条：

1. 用 `git worktree add <仓库外目录> v0.2.0` 检出旧版，**别动主工作区**；
2. `libs/` 里的前置 jar 不进 git，要手工搬过去；把存档铺成 `run/world/` 再 `runServer`；
3. 必须显式给 `GRADLE_USER_HOME=<项目>\.gradle-home`，否则会退回空的 `~/.gradle` 并重下 1.6 GB。

判定：日志出现 `Done (...)` 即不崩；`解码第 N 个条目出错` 的条数 = 该版本不认识的条目数
（0.2.0 应为 14，0.3.x 应为 0）。

### 2.4 性能（决定要不要加价格缓存）

阶段 6 **刻意没有**加价格缓存（理由见 `docs/testing/phase6-report.md` §7）。
发布前建议实测一次，用数据决定：

1. 用漏斗 / AE2 一次性往网络灌入 **10 万件**有 EMC 价值的物品；

3. 如果确实成为瓶颈，再加"物品→价格"缓存 + `EMCRemapEvent` 失效 + 对应自检；
   如果没测出问题，就保持现状并记录数值。

```groovy
// build.gradle（可选，需要 token）
plugins {
    id 'com.modrinth.minotaur' version '2.10.0'
}

modrinth {
    token = System.getenv('MODRINTH_TOKEN')
    projectId = '<你的 projectId>'
    versionNumber = mod_version
    versionName = "${mod_name} ${mod_version}"
    uploadFile = tasks.named('jar')
    gameVersions = [minecraft_version]
    loaders = ['neoforge']
    changelog = file('CHANGELOG.md').text
    dependencies {
        required.project 'beyond-dimensions'   // 以 Modrinth 上的 slug 为准
        // ProjectE 不在 Modrinth 上，无法在这里声明，需在 CurseForge 侧声明
    }
}
```
