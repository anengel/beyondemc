# 发布检查清单（阶段 7）

> 目标读者：准备发布本模组的人（或未来的自己）。
> 分三部分：**已自动验证的**、**必须人工验证的**、**发布操作**。

## 1. 已自动验证（每次启动都会跑）

启动时模组会把这五组自检写进日志（前缀 `[BeyondEMC]`），也可以在游戏内跑
`/beyondemc selftest` 手动触发。**发布前请确认全部通过**。

| 组 | 项数 | 覆盖内容 |
|---|---|---|
| 阶段 2 · 存储层 | 8 | EMC 资源类型注册、NBT/网络编解码往返、存储读写、**存储 NBT 往返（存档不丢）**、溢出保护、余额不足不为负、渲染器端侧约束 |
| 阶段 3 · 折算与学习集 | 8 | 钩子路由、**读档守卫（含 Mixin 生效性探针）**、EMC 表门禁、学习集合增删查、**集合 NBT 往返**、网络合并、LoadingGuard 语义 |
| 阶段 4 · 兑换服务 | 3+2 | 非法输入拒绝、未学习拒绝、数量边界；完整报价与防刷断言（**需 EMC 表就绪，无头环境跳过**） |
| 阶段 6 · 策略与配置 | 4 | 配置默认值、**组件物品不折算（决定性断言）**、物品筛选、策略段边界 |
| 网络接口兑换 | 5 | 铸造守卫嵌套语义、抽取上下文的保守默认、**抽取 Mixin 生效 + simulate 真值表**、配置默认值、**兑换身份一致性（防刷物品）** |
| 阶段 7 · Mixin 目标存活性 | 7+4 | 用反射核对全部 11 个注入目标是否存在（客户端专项的 4 个在专用服务器上跳过） |

**累计**：专用服务器上 **28 项通过** + 4 个目标跳过；客户端上更多（含端侧专项检查与报价断言）。

> ⚠️ **发布前必须确认这两项自检是绿的**，它们是安全断言，不是功能断言：
> - `抽取 Mixin 与 simulate 真值表` —— 保证**模拟抽取不扣费**（外部模组能力查询不会真扣钱）
> - `身份一致性` —— 保证**带组件的物品绝不会被铸造出来**（防刷物品）

### 1.1 Mixin 目标存活性：BD 升级后第一件要做的事

我们绝大多数 Mixin 用 `require = 0` 优雅降级 —— **失配时不会报错，功能会无声消失**。
阶段 7 为此加了反射核查，启动时直接告诉你：

```
OK   Mixin 目标存活性：核对了 6 个目标，全部存在（4 个客户端专项目标在专用服务器上跳过）
```

升级 Beyond Dimensions 之后，**先看这一行**。若有失配，它会逐条列出：
哪个类的哪个成员不存在了、以及对应的 Mixin 会失效。

## 2. 必须人工验证的

以下项目**无法在无头环境验证**，发布前需要真人在游戏里过一遍。

### 2.1 边界物品矩阵（`docs/plan/ROADMAP.md` §3.3）

策略层已自动验证（`Phase6SelfTest`），但**真实物品的端到端行为**没测过。

| 物品 | 期望 | 实测 |
|---|---|---|
| 石头 / 泥土（无 EMC） | 作为物品入库，EMC 不变 | |
| 钻石 / 绿宝石 | 折算成 EMC | |
| 附魔剑（锋利 V） | **不折算**（默认保护组件） | |
| 用过的钻石镐（有耐久损耗） | **不折算** | |
| 装着东西的潜影盒 | **不折算** | |
| 铁砧改过名的物品 | **不折算** | |
| 一批 6400 个钻石 | 折算正确，不溢出 | |
| 配置 `convertComponentItems=true` 后重复上面几项 | 改为折算（**会销毁组件**，确认这是你要的） | |

### 2.2 多人场景

| 项 | 期望 |
|---|---|
| 非网络成员访问 | 看不到该网络；即使伪造包指定 netId 也会被 `canAccess` 拒绝 |
| 共享网络（A 存入、B 兑换） | 两人看到同一份 EMC 与同一份学习集合 |
| **并发兑换**：两人同时兑换到余额边缘 | 余额不会变成负数（服务端串行扣费） |
| A 存入新物品时 B 正开着界面 | B 应**立即**看到新条目（增量推送） |

### 2.2b 安全性回归（每次涉及兑换的改动都要重跑）

这些是**价值完整性**断言，比功能断言重要。

| 项 | 期望 |
|---|---|
| **附魔物品**（锋利 V 钻石剑）存入 → 不折算、不学习 | 作为真实库存保留 |
| 网络接口过滤器放**附魔钻石剑** | **抽不出任何东西**，EMC 不变 |
| 网络接口过滤器放**改名物品 / 耐久镐 / 装东西的潜影盒** | 同上 |
| GUI 用改包方式请求带组件物品（若会写脚本） | 应被拒绝或降级为无组件物品，**绝不发放带组件对象** |
| **模拟抽取不扣费**：漏斗/管道对着接口做"只看不拿"查询，或反复开关红石 | EMC **完全不变** |
| 接口**不配过滤器** | 什么都抽不出，EMC 不变 |
| 接口配置已学会的**普通**物品且无库存 | 正常产出，扣费 = `数量 × 购买价`（与日志数字一致） |
| 接口配置已学会物品但**余额不足** | 不产出，EMC 不变 |
| 兑换经济性 | 任意"存入 A → 取出 A"循环**不产生净收益**（`购买价 ≥ 回收价`） |

### 2.3 模组共存

| 组合 | 关注点 |
|---|---|
| + JEI / EMI | 虚拟条目的拖拽、配方查询是否异常 |
| + AE2 / RS（若装了 BD 的对应集成模块） | 网络接口存取是否照常；EMC 不应被物流抽取 |
| 只装 BD + ProjectE + 本模组 | **最小环境**：确认没有隐藏的必需依赖 |

> 开发环境本身就是**最小环境**（只有 BD + ProjectE + 本模组），
> 所以"最小环境能否启动"其实已被反复验证；上表的后两行才是增量。

### 2.4 性能（决定要不要加价格缓存）

阶段 6 **刻意没有**加价格缓存（理由见 `docs/testing/phase6-report.md` §7）。
发布前建议实测一次，用数据决定：

1. 用漏斗 / AE2 一次性往网络灌入 **10 万件**有 EMC 价值的物品；
2. 观察 MSPT（`/debug start` 或 Spark）与是否有明显卡顿；
3. 如果确实成为瓶颈，再加"物品→价格"缓存 + `EMCRemapEvent` 失效 + 对应自检；
   如果没测出问题，就保持现状并记录数值。

### 3.3 发布到 CurseForge / Modrinth

模组依赖已声明在 `neoforge.mods.toml` 里，**不需要**把两个前置模组打进包里。

```groovy
// build.gradle（可选，需要 token）
plugins {
    id 'com.modrinth.minotaur' version '2.10.0'
}

modrinth {
    token = System.getenv('MODRINTH_TOKEN')
    projectId = '<你的 projectId>'
    versionNumber = mod_version
    versionName = "${mod_name} ${mod_version}"
    uploadFile = tasks.named('jar')
    gameVersions = [minecraft_version]
    loaders = ['neoforge']
    changelog = file('CHANGELOG.md').text
    dependencies {
        required.project 'beyond-dimensions'   // 以 Modrinth 上的 slug 为准
        // ProjectE 不在 Modrinth 上，无法在这里声明，需在 CurseForge 侧声明
    }
}
```

> ⚠️ **CurseGradle 插件（`com.matthewprenger.cursegradle` 1.4.0）已过时**
> （最后更新 2019 年），建议用 CurseForge 网页端上传，或改用较新的替代方案。

### 3.4 升级前置模组之后的回归

BD / ProjectE 有新版本时，**先做这两件事**，再看别的：

1. 启动看 `Mixin 目标存活性` 那一行 —— 失配会直接列出失效目标；
2. 跑 `/beyondemc selftest`，确认五组自检仍全绿。

然后按 §2.1–§2.3 重跑人工验证。若 Mixin 目标改名了，改动点集中在
`src/main/java/com/zhuyuhang/beyondemc/mixin/` 下的 5 个类，
以及 `diag/MixinTargetCheck.java` 里的目标清单（**两处都要改**）。
